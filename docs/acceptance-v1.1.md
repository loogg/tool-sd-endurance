# v1.1 验收记录

日期：2026-10-02。独立仓库：`tool-sd-endurance`。本轮以用户对 v1.0 的六项反馈为验收依据，继承 Figma 视觉系统与模型 00；原始交付包和首版验收记录保留。

| 用户反馈 | 实现与验证 |
|---|---|
| 自定义没有型号 / 容量入口 | 可选型号、标称容量在主界面显示，并进入来源快照；容量不参与主机预算公式，也不替代有效 NAND 循环池 |
| P/E 入口位置不同 | A / B 使用同一位置的计算方式按钮组，分别标记常用 / 高级；两种模式独立保留数据 |
| 不理解 P/E、普通用户是否需要 | 入口说明、字段帮助与计算原理解释 NAND 编程 / 擦除循环，并引导普通用户使用 TBW 或两参数选型 |
| 历史未知让结果全为空 | 保留已知总预算和年度未来写入需求，提供补充历史、带入负载算选型；不虚构剩余量或时间，编辑后保持上次成功快照 |
| 预设型号过少、缺 8 / 16 GB | 扩至 5 厂商、44 个型号 / 容量组合；品牌与容量可筛选，来源、代际、停产状态和限制可查 |
| 选择预设还要手填 | 自动填写公开卡片规格 / 适用的数值；动态列出尚缺输入；私人负载与历史不由预设推定；未明确计数口径的 TBW 采用显式假设确认 |

## 计算与来源

A 的 `max(E − H, 0)`、B 的 `max(C × P/E − N, 0) / WAF_future`、D 的 `q × 365 × Y` 以及单位和快照规则保持。未知历史仍使现有卡剩余量 / 时间为 null；新增年度写入需求为同一成功快照的 `q_TB × 365`，通过有限值检查。

低容量预设逐型号引用：Kingston SDCIT2 8 / 16 / 32 / 64 GB 不继承最高容量 3,840 TBW；Transcend USD230I 使用厂商逐容量表。Samsung / SanDisk 的录像耐久小时保留原指标。消费卡容量、速度、保修年限均不转为耐久值。详细来源见 [预设资料](card-presets.md)。

## 检查与独立审核

`npm ci` 干净安装，依赖审计0漏洞；最终 lint、24 项模型 / 预设测试、44 项 E2E、生产构建通过。E2E 覆盖数值、快照、预设采用 / 清空、筛选保留、模式隔离、未知恢复、工程参数保留、A / B 完整词组的真实行位置，以及全部25个尺寸。
